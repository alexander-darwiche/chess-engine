This page summarizes the major algorithms and implementation methods used in this chess project.

Engine/search methods

MethodWhat it doesWhere used
Iterative deepening Searches depth 1..N and keeps the best move found so far if time runs out. mcts_ai.py, MCTS_ai.play
Alpha-beta pruning Cuts branches that cannot influence the final decision to search deeper with less work. mcts_ai.py, _alphabeta
Transposition table Caches previously evaluated positions in the current search to avoid recomputation. mcts_ai.py, self.transposition
Quiescence search Extends tactical positions (captures/check pressure) past nominal depth to reduce horizon effects. mcts_ai.py, _quiescence
Null-move pruning Tries a “pass” move in safe positions; if still good, prunes aggressively. mcts_ai.py, _alphabeta
Late move reductions (LMR) Searches low-priority quiet moves at reduced depth, then re-searches only if promising. mcts_ai.py, _alphabeta
Principal variation style windows Searches first move wide, later moves narrow first; re-searches if needed. mcts_ai.py, _search_root
Aspiration windows Starts each deeper iteration near previous score to speed convergence. mcts_ai.py, play
Move ordering (history + killer + tactical bonuses) Sorts stronger candidate moves first to improve pruning quality. mcts_ai.py, _order_moves
Opening book Uses predefined common opening lines to play strong opening moves quickly. mcts_ai.py, OPENING_BOOK

Evaluation methods

  • Material values (pawn/knight/bishop/rook/queen/king baseline).
  • Piece-square tables for positional bonuses by square.
  • Center control bonus based on distance to center.
  • Pawn structure penalties (isolated/doubled tendencies).
  • Development and king safety heuristics.
  • Pseudo-mobility heuristic for move activity.

Game-state correctness methods

  • Check/checkmate and stalemate resolution logic.
  • Threefold repetition detection from tracked position history.
  • 50-move rule tracking via halfmove clock.
  • Insufficient material handling for specific draw cases.
  • Post-move legality filtering through the chess rules engine.

Coach chatbot methods

  • Strands-style chat loop with stored conversation history per session.
  • Tool snapshot extraction before each answer: opening guess, candidate checks, candidate captures, detected pins, and pressure map.
  • Local LLM generation through Ollama when available.
  • Graceful fallback reasoning from tool results if model calls fail/timeout.

Frontend visualization methods

  • Interactive board with drag/drop and click-to-move.
  • Live search-tree simulation with depth bands, principal-path highlighting, and activity stats.
  • Collapsible right-panel UI sections for status/controls/tree/moves.
  • Chat-style coach UI with quick prompts.
